# 本版与最早版本的主要区别

## 1. 信赖域接受规则

最早版本使用真实 STCH 函数值判断候选点是否被接受。只要候选点满足 STCH 下降，即

```text
act_red > 0
```

就接受该候选点。此时，下降比率 `rho_k` 只用于调整信赖域半径，并不决定候选点是否被接受。

最新版按照论文中的信赖域框架，使用原始加权 Tchebycheff 子问题的真实下降作为分子，使用 STCH 局部模型的预测下降作为分母：

```text
rho_k = [Phi_lambda(x_k) - Phi_lambda(x_k+s_k)]
        / [G_mu,lambda(x_k) - G_mu,lambda(x_k+s_k)]
```

只有当

```text
rho_k >= eta_1
```

时，候选点才会被接受。否则，候选点被拒绝，并按照信赖域规则调整半径。因此，最新版能够避免接受“平滑 STCH 值下降，但原始 Tchebycheff 子问题没有获得可靠改善”的候选点。

## 2. 动态平滑参数 mu_k

最早版本采用如下动态平滑参数：

```text
mu_k = min(mu_max, c_mu * Delta_k)
```

即 `mu_k` 与当前信赖域半径 `Delta_k` 成正比。

最新版采用：

```text
mu_k = min(mu_max, kappa_mu * c_mu * Delta_k^2 / log(q))
```

即 `mu_k` 按照 `Delta_k^2` 的尺度动态缩小，使其与论文中函数模型误差的二阶尺度保持一致。

此外，最新版增加了固定缩放参数：

```text
kappa_mu = 10
```

该参数用于控制动态 `mu_k` 的整体数值尺度。`kappa_mu=10` 是在固定 `n`、`N`、函数评价预算、`p` 和 `c_mu` 的条件下，通过联合比较 ZDT1 和 ZDT2 的 IGD、间距变异系数、最大间隙和超体积后选取的经验折中值。它不是由论文理论推导得到的最优值，也不能保证在其他问题上仍然最优。真正代入 STCH 标量化函数的参数仍然是随迭代动态变化的 `mu_k`。

## 3. 无导数局部模型的构造

最早版本从全局评价归档中选择当前点附近的历史采样点，计算这些采样点对应的 STCH 函数值，然后通过伪逆最小二乘方法拟合线性模型：

```text
m(x) = g_0 + grad(m(x_0))' * (x-x_0)
```

参数 `p` 同时影响拟合模型时使用的历史点数量。当历史采样点在当前信赖域内分布不均匀或几何条件较差时，由最小二乘拟合得到的模型梯度可能不稳定。

最新版在当前信赖域内沿坐标方向评价邻近点，并仅使用目标函数值构造局部 STCH 模型梯度：

```text
[grad G_mu_k(x_k)]_j
    ~= [g_mu_k(x_k+h_j*e_j) - g_mu_k(x_k)] / h_j
```

该过程没有调用任何目标函数的解析梯度，只使用 `f(x_k)` 和邻近点 `f(x_k+h_j*e_j)` 的函数值，因此仍然属于无导数优化。这里得到的是 STCH 局部代理模型的近似梯度，而不是真实目标函数的梯度。相比从随机历史点进行回归，坐标几何点能够提供更加明确的局部方向信息。

## 5. 建模归档与解归档

最早版本只维护一个全局归档。初始化点、几何修复点、被接受的候选点以及被拒绝的候选点都会存入同一个全局归档。该归档主要用于局部模型构造，但在子问题发生停滞并重新启动时，算法也会从整个全局归档中重新选择当前解。因此，没有通过信赖域接受条件的点可能通过停滞重启机制间接回到当前种群。

最新版将归档划分为模型归档和解归档。模型归档保存所有已经评价的点，仅用于构造局部模型和更新理想点。解归档只保存初始化点以及满足

```text
rho_k >= eta_1
```

的已接受候选点。未通过接受条件的几何建模点和候选点不能直接进入解归档，也不能作为最终 Pareto 前沿点。

因此，最新版最终 Pareto 前沿的均匀性不是由 LHS 初始化或大量几何采样点直接填充得到的，而是由 p-MODFTR 的信赖域接受机制和分解协作机制产生的。

## 6. 不同分解子问题之间的信息共享

最早版本中的所有子问题共享全局建模数据，因此不同子问题可以使用全局归档中的邻近点构造自己的局部模型。但是，当第 `i` 个子问题接受一个新候选点时，算法只更新该子问题对应的当前解：

```text
X_i <- x_new
F_i <- F(x_new)
```

其他权重对应的子问题不会立即检查该新解是否也能够改善自己的 Tchebycheff 标量化值。因此，最早版本主要实现了建模数据层面的共享，没有实现已接受解在不同分解子问题之间的完整协作。

最新版将所有通过信赖域接受条件的候选点存入共享解归档。一个子问题发现的新解会被其他权重向量重新计算其 Tchebycheff 标量化值。如果该点能够改善其他权重对应的子问题，则其他子问题也可以使用该点更新自己的代表解。

因此，最新版不仅共享模型构造数据，还增加了已接受解在不同分解子问题之间的协作，提高了有限函数评价预算下的信息利用效率。

## 7. 最终 Pareto 前沿的生成方式

最早版本直接对迭代结束时的当前种群 `FC` 进行非支配过滤：

```matlab
nd = nd_idx(FC);
results.F = FC(nd,:);
```

这种方式只使用算法最后一次迭代结束时各个子问题的当前点，不会重新检查优化过程中曾经找到、但后来被其他点替换的优质解。因此，最终结果中可能存在停滞点、重复点、相互距离过近的点，或者尚未充分收敛的当前点。

这版在算法结束时，针对每一个权重向量扫描整个已接受解归档，并重新选择该权重对应的加权 Tchebycheff 值最小的代表点。随后，算法删除重复代表点，并对剩余点执行非支配过滤。

因此，最新版最终 Pareto 前沿利用了整个优化过程中所有通过信赖域条件验证的解，而不是只依赖最后一轮种群状态，从而减少了由于子问题停滞或最终状态偶然性造成的前沿分布不均匀问题。
